# 数据库时间规则

## 写入与读取

本次调整从 Alembic `0006` 开始生效：

- 新增业务数据的所有 `DATETIME` 字段写入北京时间 `UTC+08:00`
- 已有时间字段保留数据库中的原始值，不批量增加 8 小时、不重建业务记录、不删除业务数据
- 原记录后续正常产生的业务更新，例如最近播放、最近点击、链接解析或缓存刷新，其被更新的时间字段使用新的北京时间规则；未被更新的创建时间、首次时间仍保留原值
- 时间比较、自动复检、链接过期和个人记录排序仍依据真实时间点，不直接比较混合时区的原始字符串
- 接口继续返回带时区的 ISO 时间或 Unix 毫秒时间戳，小程序无需再手动增加 8 小时
- JSON 缓存中的 ISO 时间字符串和 Unix 时间戳不属于无时区的 `DATETIME` 字段，不进行整体平移
- `user_history_state` 和 `alembic_version` 没有日期字段，无需修改时间

应用每次连接 MySQL 时执行 `SET time_zone = '+08:00'`，只设置本连接，不修改数据库全局时区或依赖腾讯云管理员权限；固定偏移不依赖容器的系统时区，也不要求安装 MySQL 时区表

## 为什么增加内部标记

同一行可能同时有原来的 UTC 创建时间和刚更新的北京时间，不能仅按整行或日期分界猜测时区

为有时间字段的 9 张业务表增加 `time_storage_mask` 内部列：

- 迁移前已有记录标记为 `0`，原有时间按 UTC 解释，时间字段值不改动
- 新记录默认使用 `8191`，时间字段均按北京时间解释
- 对旧记录进行业务更新时，只设置本次实际写入字段对应的标志位，不转换同一行中其他历史时间
- 该列仅用于服务端读写，普通歌曲和个人接口不向客户端返回，不应手动修改

数据库查询工具会同时看到旧记录的原始 UTC 值和新记录的北京时间，这是按要求保留历史值的结果，不代表程序排序或最近播放时间会偏移

开发时新增时间字段需要同步追加稳定标志位，禁止调整或复用既有标志位；直接执行 Core UPDATE 或 UPSERT 时需同步设置对应标记，时间排序使用统一的 `utc_expression`，业务层不直接操作无时区时间

## 部署顺序

本次包含数据库结构升级，不能只更新容器代码，也不能混跑旧版和新版写入程序，新版启动时会检查标记列，未升级时明确报错并停止启动，不会先运行后台采集

1. 先对 MySQL 做常规备份，停止旧服务实例，包括后台采集与复检任务
2. 使用 `music_migrate` 连接目标数据库，执行下面的结构升级
3. 确认 Alembic 版本为 `0006`
4. 部署包含本次改造的 FastAPI，生产仍由 `music` 运行账号连接内网 MySQL
5. 恢复调用，检查新歌曲、新播放会话和用户记录的时间

```powershell
uv run alembic upgrade head
uv run alembic current
```

迁移连接由 `MUSIC_MIGRATION_DATABASE_URL` 提供，不将迁移账号写入生产容器，不需要增加新的环境变量

迁移仅增加内部列并调整其默认值，不执行 `UPDATE ... SET 时间字段 = DATE_ADD(...)`，不将历史时间转成北京时间；生产 MySQL 的 DDL 不保证整组操作可回滚，发生中断后保持停止写入，修复故障后可以重新运行升级，已有标记列不会被再次初始化

版本升级与已有数据处理是两件事，执行 `0006` 不会使已有时间字段变成北京时间，只有后续新写入的值采用北京时间

## 检查示例

确认应用连接时区：

```sql
SELECT @@session.time_zone, NOW(), UTC_TIMESTAMP();
```

此查询需在应用连接中执行，数据库查询工具会创建自己的会话，可能显示不同的 `@@session.time_zone`

查看最新写入的原始值：

```sql
SELECT id, created_at, updated_at, time_storage_mask
FROM songs
ORDER BY id DESC
LIMIT 10;
```

新插入歌曲的 `created_at` 应为当时的北京时间，老歌曲原来的 `created_at` 不应变化，`updated_at` 只在业务正常更新时改变

## 测试与回退

测试覆盖新字段北京时间写入、原值原样保留、混存后的比较与排序、旧记录部分字段更新、首次统计不重写、Unix 时间戳不变和重复执行结构升级

另有仅允许回环地址和专用空测试库的真实 MySQL 测试 `tests/test_time_mysql.py`，普通测试默认跳过此项，不会尝试连接线上数据库

只要已有北京时间写入，禁止直接降级并删除时区标记，否则旧代码会把这些值误认成 UTC；需要回退时使用部署前备份，不在本次实现中自动转换历史时间
