# 原生微信音乐小程序

## 当前交付阶段

当前交付为第一阶段“直连与后台音频真机验证版”，包含原生发现／搜索验证页面、全局背景播放器和独立事件页面，不是最终完整页面

方案约定先通过真实设备后台播放，再完成与 Web 对齐的完整发现页、情绪入口、推荐卡片和封面布局，未通过前不宣称完整小程序已经完成

- 使用 TypeScript、WXML、WXSS，不使用 web-view，不改造或替换现有 Web
- AppID 为 `wxe1af0ed55ed257b7`，云环境为 `prod-d1ghaho8i283f4b26`，服务名为 `music`
- API 全部通过 `wx.cloud.callContainer`，源码不依赖云托管公网域名
- 音频使用实际音乐平台的 HTTPS 临时地址，通过 `wx.getBackgroundAudioManager()` 播放
- 不存储整首音频，不返回 Cookie 或专用请求头，不回退试听，不在播放中途换源
- 使用手机系统音量，不提供背景播放器不支持的音量滑块
- 上传代码仅进入开发版本，不提交审核、不发布正式版，不使用 AppSecret

## 后端先部署

先在微信云托管重新部署包含本次代码的版本，保持端口 80、单 worker，控制台最大实例数必须改为 1，不使用截图中原来的 5

原因是 SQLite、播放会话与限流都在单实例内，多副本会出现会话不存在和限流不一致，当前没有迁移到共享数据库

启动自动执行 Alembic `0003`，新增 playback_sessions.transport，旧会话默认 proxy，新小程序会话为 direct，保留原有详情和统计

| 小程序接口                                   | 用途                                           |
| -------------------------------------------- | ---------------------------------------------- |
| POST /api/miniprogram/songs/{id}/playbacks   | 实时获取已验证完整版并做无专用请求头的直连预检 |
| GET /api/miniprogram/playbacks/{id}          | 查询会话、实际音源、链接版本及临时 audio_url   |
| POST /api/miniprogram/playbacks/{id}/started | 实际 onPlay 后按会话幂等记录一次有效播放       |
| POST /api/miniprogram/playbacks/{id}/refresh | 当前实际音源最多刷新一次，不中途换源           |

列表复用 /api/home、/api/search、/api/sources，Web 的 stream_url 和代理播放接口不改变

- 直连预检复用有界音频时长读取与公网 IP 固定代理，仅允许 HTTPS，所有重定向也禁止降级为 HTTP
- 返回 direct_audio_unsupported 表示无法无专用请求头读取当前完整版，或不兼容当前直连方式，不会全局隐藏 Web 可播放歌曲
- 返回 full_audio_unavailable 表示实际音源无法取得可靠完整版，沿用暂时隐藏和定期复检
- 两类会话不能混用接口，Web started 仍必须在代理开始传输后上报，小程序 started 允许 ready 后按实际播放事件上报
- 小程序开始播放是客户端声明，服务器无法独立证明用户确实听到声音，该统计不用于计费或可信审计
- 小程序刷新与创建同样受动作频率、搜索与线程池容量限制，音频直连不占服务器音频代理并发，但仍受音乐平台网络和权限限制

默认关键词继续以 .env.example 为唯一来源，不在小程序硬编码另一份首页推荐关键词

## 本地构建与导入

需要与现有前端兼容的 Node.js 和 npm，在项目根目录执行：

```powershell
cd miniprogram
npm ci
npm test
```

微信开发者工具导入仓库内的 miniprogram 目录，读取 project.config.json，编译目录为 dist，构建后的 JS、WXML、WXSS、JSON 都在该目录

开发者工具建议使用最新稳定基础库，project.config.json 的基础库选择仅作为开发工具配置，不代表声明更低版本也可正常运行

不关闭域名合法性校验，不把“关闭校验后模拟器可以播放”作为真机验收，若微信提示实际音源域名或权限限制，需要记录真实报错并核实合法域名及账号权限，不强行绕过

## 本机自动上传

上传密钥放在仓库外，配置小程序代码上传的 IP 白名单，本机公网出口 IP 变化后需重新核对，不提交上传私钥或 AppSecret

上传命令会先运行构建和 19 项测试，检查 AppID、已提交 Git 状态、私钥及产物后再调用微信官方 miniprogram-ci

```powershell
cd miniprogram
$env:WECHAT_UPLOAD_KEY_PATH = '仓库外上传私钥的绝对路径'
npm run upload
```

- 版本号为 package.json 版本加短 Git 提交号，备注明确标注验证版，实际返回成功才报告已上传
- 默认上传机器人编号为 1，可通过 WECHAT_UPLOAD_ROBOT 设置 1～30，不自动提交审核或发布正式版
- 上传可能替换该机器人对应的现有开发版本，正式线上小程序不由此命令发布
- 密钥只从本机读取，不复制到源码、dist 或日志，源码含未提交变更时停止上传
- 上传结果保存在被 Git 忽略的 miniprogram/.local/last-upload.json，不包含私钥和音频链接
- 本机安装的微信官方上传工具有已知依赖安全告警，使用时只处理本仓库可信代码，不将其暴露为上传服务，不进入后端容器或小程序运行包，未宣称依赖告警已修复

上传失败根据错误提示检查私钥、出口 IP、微信网络、AppID 和后台权限，不无限重试，不把编译成功当成上传成功

构建会检查 WXML 表达式，禁止将 `<=`、`&&` 等运算符写成 `&lt;=`、`&amp;&amp;`，正文中的 HTML 实体不受影响，避免本地编译通过但微信上传侧校验失败

本次微信返回上传出口不在白名单，需小程序管理员在公众平台“开发管理 → 开发设置 → 小程序代码上传 → IP 白名单”中添加实际上传出口后再执行，不能把云托管出口 IP 当成本机上传 IP，也不建议关闭白名单

脚本只在微信错误明确包含有效 IPv4 时展示该 IP，不通过第三方服务查询出口、不显示完整平台响应或私钥，无法确定时由管理员核对网络出口

## 真机与后台播放验收

1. 后端部署到最新提交，控制台最大实例数为 1，确认小程序对目标云环境有调用权限
2. 打开验证版，点击“检查连接”，确认健康接口正常，云公网关闭后也需可调用
3. 选择真实已验证歌曲，确认开始播放后实际音源名称和进度正常，不能以列表总时长代替音频实际时长
4. 打开播放事件页，确认切换页面不打断播放
5. 切到微信聊天，锁屏至少 30 秒，测试耳机播放暂停、上一首和下一首，再回到小程序
6. 快速切歌、拖动进度、断开再恢复网络，确认旧请求不覆盖新歌曲，最多刷新一次，不能降级为试听
7. 记录手机系统、微信版本、测试时间、实际音源、错误码和结果，不提交临时音频地址或私钥

后台音频能力及上架类目需以当前账号和真机结果为准，若个人主体权限受限，明确记录阻塞，不静默改用前台播放器或公网代理
