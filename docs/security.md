# 安全与服务器部署

## 公开访问与资源保护

- 所有页面、静态资源、搜索、播放接口和音频流默认公开访问，浏览器打开即可使用，不弹出账号密码框
- 不再使用 MUSIC_ACCESS_USERNAME 和 MUSIC_ACCESS_PASSWORD，旧 .env 或控制台中的这两个变量会被忽略，可以删除，空值或旧短密码不会阻止启动
- 取消的是共享密码门槛，不是资源保护，请求限速、搜索任务上限、有界验证队列和音频并发限制继续生效
- 使用 HTTPS 或 SSH 隧道保护传输，公开服务需要配置流量、费用和监控告警，本项目不提供注册登录和多用户数据隔离
- GET /api/health 只返回服务和数据库健康状态，与其他接口一样受请求限流保护
- 允许用户从其他网站点击链接进入本页，浏览器跨站子资源请求和 iframe 嵌入仍被拒绝，避免第三方页面直接消耗本服务资源

## 默认关键词的唯一来源

- 默认 MUSIC_KEYWORDS 直接从仓库的 .env.example 读取，保留用户在该文件中维护的原值，不在 Python 或云模板里另存一份关键词
- Docker 构建会复制 .env.example，后续修改该文件后重新部署镜像即可更新默认值，已有候选缓存会按原缓存策略刷新
- 显式运行环境变量优先于本地 .env，本地 .env 优先于 .env.example 中的默认关键词
- 如果以前在本地 .env 或云控制台填过旧的 MUSIC_KEYWORDS，删除该覆盖项即可随 .env.example 更新，保留其他配置，不要覆盖整个 .env
- 保持 MUSIC_KEYWORDS 为 JSON 字符串数组，默认值无效或缺失时明确报配置错误，不静默改回另一组词

## 新增配置

部署时按需调整以下参数，不需要设置访问账号密码，也不要覆盖已有数据库配置

| 环境变量                      | 默认值 | 含义                                                                       |
| ----------------------------- | ------ | -------------------------------------------------------------------------- |
| MUSIC_REQUEST_CONCURRENCY     | 16     | 普通 HTTP 请求最大在途数，音频流单独计数                                   |
| MUSIC_REQUEST_RATE_PER_MINUTE | 120    | 每 IP 每分钟总请求数，包含静态文件、健康检查和音频请求                     |
| MUSIC_ACTION_RATE_PER_MINUTE  | 20     | 每 IP 每分钟创建播放和主动刷新请求的总数                                   |
| MUSIC_SEARCH_TASK_LIMIT       | 4      | 同时存在的搜索后台任务上限，同搜索条件合并，不按轮询次数创建任务           |
| MUSIC_PROVIDER_QUEUE_SIZE     | 6      | 音乐平台线程池额外等待任务数，不含 MUSIC_PROVIDER_CONCURRENCY 个执行中任务 |
| MUSIC_VERIFICATION_QUEUE_SIZE | 100    | 后台验证等待队列容量，不含最多 2 个执行中任务                              |
| MUSIC_STREAM_CONCURRENCY      | 6      | 全局音频连接上限，不等于保证 6 人流畅播放                                  |
| MUSIC_STREAM_PER_IP           | 3      | 同 IP 音频连接上限，共享公网 IP 的用户共用额度                             |
| MUSIC_STREAM_PER_SESSION      | 2      | 同一播放会话连接上限，为浏览器拖动进度保留余量                             |
| MUSIC_STREAM_MAX_SECONDS      | 900    | 单条音频 HTTP 连接最长存活秒数，超时中断连接，不会把歌曲标记为不可用       |

所有限制均在单进程内生效，必须保持 `--workers 1`、单实例运行，不能通过增加 worker 绕过限制

音频元数据解析也使用有限容量的线程池，请求取消后，实际线程结束前仍占用额度，避免超时后不断堆积任务

## 达到限制时的行为

- 超过请求频率、同 IP 或同会话连接上限：返回 `429` 和 `Retry-After`
- 普通请求、全局音频连接、搜索或线程池容量耗尽：返回 `503` 和 `Retry-After`，不继续无界排队
- 搜索已有旧缓存时优先展示旧缓存并提示繁忙，新关键词没有缓存时明确返回繁忙
- 验证队列装满时，候选歌曲仍保留在数据库，队列消费和每分钟扫描会继续补入，不删除或永久排除歌曲
- POST 请求体最多 16KiB，超过返回 `413`，接收请求体超过 10 秒返回 `408`
- 音频已输出后超时不会拼接 JSON 错误，连接会关闭，浏览器可能只显示通用播放错误，可以稍后重新点击播放
- 刷新次数耗尽只拒绝额外刷新，不隐藏正常歌曲，也不修改正常会话，只有实际音源验证或音频传输失败才走暂时隐藏流程
- 本地线程池繁忙不等于音源不可用，创建播放会返回繁忙，刷新会保留原链接和刷新额度

并发限制不是流量套餐，仍需要在云平台配置流量和费用告警，不保证 100 人同时播放

## 网络与部署

- 当前镜像默认监听 80，微信部署见 [微信云托管](wechat-cloudrun.md)，与本地开发的 8000/5173 端口互不影响
- 自有服务器测试时先用 `docker build -t music-web .` 构建，再用 `docker run -d --name music --restart unless-stopped --env-file .env -p 127.0.0.1:10000:80 -v music-data:/app/data music-web` 启动，保持 `.env` 中的 `PORT=80`
- 在自己电脑运行 `ssh -N -L 18000:127.0.0.1:10000 用户名@服务器IP`，浏览器访问 `http://127.0.0.1:18000`，安全组不开放 10000、8000、5173
- 公网部署时使用 HTTPS 反向代理，后端仍绑定回环地址，限制上传大小、连接数和慢连接，并配置日志轮转
- 程序不直接信任 X-Forwarded-For，Docker 默认使用 `--no-proxy-headers`，防止用伪造请求头绕过 IP 限制
- 该默认模式下，反向代理访问可能统一按代理 IP 计数，对小范围测试更保守；若需识别真实 IP，必须先在可信代理处覆盖客户端提交的转发头，再仅信任该代理，不要直接设置 `--forwarded-allow-ips="*"`
- 保持非 root 容器用户和命名数据卷，更新镜像不删除 `music-data` 卷
- 旧部署中的账号密码配置可以移除，微信和 Render 模板不再重复定义 MUSIC_KEYWORDS，统一使用随镜像打包的默认值

## 更新与备份

1. 修改前备份数据库，简单可靠的方式是停容器后复制整个数据卷目录，同时保留 SQLite 的 WAL/SHM 文件，不在运行中只复制单个数据库文件
2. 拉取代码，检查新增环境变量并重新构建镜像
3. 停止、移除旧容器，使用相同的 `music-data` 卷和 `.env` 启动新容器，不删除数据卷
4. 检查健康接口、首页无需密码、匿名搜索及实际歌曲播放

本次加固不包含 cryptography 依赖兼容性升级、数据库过期记录清理、多用户隔离或音乐授权，已知依赖告警仍需后续单独处理
